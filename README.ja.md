# ファイル名を指示にする

**読み方の制約は、ファイルの中ではなく、ファイル名に書く。**

「このファイルは最後まで読ませたい」を、AIコーディングエージェントに守らせる
ための手法です。手数は `mv` 1回。追加の費用はゼロ。ファイルを開く前に効きます。

英語版：[README.md](README.md)

## すぐ使う

1. AIに必ず最後まで読ませたいファイルを1つ選ぶ（設計書・仕様書など）。
2. 名前に読み方の制約を入れて付け直す。

```
mv 設計思想.md "設計思想(部分閲覧禁止).md"
```

3. そのファイルを指している場所（`CLAUDE.md`・リンク・スクリプト）のパスを直す。古いログは書き換えない。

これだけです。付けるのは少しのファイルにとどめてください。全部に付けると目立たなくなります。なぜ効くのか、限界は下に書いてあります。

---

## 何が困るのか

エージェントはファイルを途中までしか読まず、そのまま自信を持って作業を進めます。

これはよく知られた現象です。読み取りツールは黙って打ち切ります。長い文脈では
両端が強く、真ん中が薄くなります。エージェント向けの指示ファイル自体も切られます
（Codex は複数の `AGENTS.md` を連結したうえで上限で切るため、最後のファイルの
末尾に書いたルールは、モデルが読む時点で存在しません）。文脈の圧縮を数回くぐると、
ファイルを読まずに `grep` で拾う癖に戻ります。

やっかいなのは、**中からは失敗が見えない**ことです。ファイルはディスクにあり、
エディタにも表示され、レビューにも出てきます。エージェントはその一部だけを読み、
どこを読まなかったかを申告する手段を持ちません。

## よくある対処と、その置き場所

広く共有されている対処は、置き場所で2つに分かれます。

- **ファイルの中** — 冒頭に「最後まで読め」と書く／`要約するな` と書く
- **別の場所** — `CLAUDE.md` や `AGENTS.md` のルール、`PreToolUse` フック、
  「全部読んだ」という発言を差し戻す `Stop` フック、スキル

どちらにも同じ穴があります。**ファイルの中に書いた指示は、開いてからしか効きません。**
135行目から8行だけ開けば、冒頭の指示は最後まで文脈に入りません。別の場所に置いた
ルールは効きますが、そこで別途保守する必要があります。

## やること

制約を**ファイル名**に入れます。

```
設計思想.md
→ 設計思想(部分閲覧禁止書物).md
```

これだけです。`mv` 1回。

ファイル名は、フォルダを一覧した瞬間、パスを解決した瞬間、ツールの結果が返った
瞬間に、すでにエージェントの文脈へ入っています。**どこまで読むかを決めるより前**です。
だから、部分的に読んでこれを飛ばす、という経路が存在しません。

## 位置がすべて

| 置き場所 | いつ効くか | 部分読みで素通りできるか |
|---|---|---|
| ファイル冒頭の宣言 | 開いた後 | **できる**（400行目から開けば読まれない） |
| `CLAUDE.md` のルール | セッション開始時 | できない。ただし毎回の文脈を消費する |
| `PreToolUse` フック | 最初の道具を使う直前 | できない。ただし設定とスクリプトが要る |
| **ファイル名** | **開く前** | **できない** |

## 実際に観測したこと

長期運用しているエージェント作業場からの3件です。**いずれも n=1**。対照実験では
なく、現場の観察です。

**ケース1 — 冒頭の宣言が効きようがなかった。** ある回に、文書の一節だけを読むよう
指示されたエージェントが、8行の範囲だけを開きました。その文書の冒頭には「最後まで
読む以外の選択肢は残されていない」という強い宣言が置かれています。その行は一度も
文脈に入りませんでした。**宣言はよく書けていて、構造的に発動できなかった**わけです。

**ケース2 — 名前が、開く前に効いた。** 同じ文書のファイル名に制約を入れて改名した
あと、別の回に部分読みを頼まれたエージェントは、**読み取りを1回も実行しないうちに**
断りました。理由としてファイル名を挙げています。

**ケース3 — 「流し読み」の正体。** 流し読みを指示されたエージェントが報告したのは、
「自分に流し読みという動作は無い」ということでした。できるのは①読む量を減らす
②注意の深さを減らす、の2つだけです。①をファイル名で塞ぎ、②を冒頭の宣言で塞ぐと、
最後まで注意して読む以外に道が残りません。

## 手数

| やり方 | 導入の手数 | 他のツールへそのまま持っていけるか |
|---|---|---|
| **ファイル名** | **1手**（`mv`） | **そのまま効く** |
| ファイル冒頭に書く | 守らせたいファイルの数だけ | 効く |
| `CLAUDE.md` に書く | 1手＋毎回の文脈消費 | 製品ごとに置き場所が違う |
| `PreToolUse` フック | 設定＋スクリプト＋動作確認 | 書き直しが要る |
| 検算用フック | スクリプト＋テスト一式 | 書き直しが要る |

## 限界

採用する前に、ここを読んでください。

- **強制力はありません。** 名前は説得するだけで、止めるのはフックです。確実に
  止めたいならフックが要ります。これは**いちばん外側に無料で足せる1枚**であって、
  フックの代わりではありません。
- **引用してくる相手には届きません。** 別のエージェントが抜粋だけを渡してきたら、
  受け取る側はファイル名を見ません。制約はファイルについて回りますが、その中身に
  ついては回りません。
- **改名すると参照が壊れます。** そのファイルを名指ししている箇所を全部直す必要が
  あります。ただし当時の記録（ログ・議事録・スナップショット）は**直してはいけません**。
  書き換えれば記録の捏造になります。
- **珍しいから効きます。** 全部のファイルにこの名前を付けると、目印としての力を失います。
- **環境に依存します。** アップロード型のインターフェースでは、ファイル名がモデルに
  渡らないという報告があります。自分の環境で確かめてから頼ってください。
- **攻撃と同じ仕組みです。** ファイル名を経由したプロンプトインジェクションは既知の
  脅威です（OWASP LLM01）。これはその仕組みを、自分のファイルへ向けたものです。
  外部から受け取るファイル名の無害化は、引き続き必要です。

## 先行研究

部品はすべて既知です。部品を自分のものだとは主張しません。

- **ファイル名をAI向けのメタデータにする。** 用途を頭に付ける（`AI引き継ぎプロンプト_…`）、
  ISO 8601 の日付を頭に置く、連番で読む順を固定する、検索に効く語を入れる。広く
  実践されています。ただしそこに載せているのは**そのファイルが何か**であって、
  **どう読むべきか**ではありません。
- **読み方そのものを制約する。** 「要約するな」「意訳するな」「フォルダごと一括で
  読み込むな」。これも実践されています。ただし置き場所はファイル本文か、隣接する
  別の制御文書で、**開いてからしか効きません**。
- **ファイル名を命令の位置として扱う。** これは**攻撃側**で確立しています。ファイル名
  経由のインジェクション、不審なファイル名の検出器、「生のファイル名を命令の位置に
  置くな」という OWASP の緩和策。
- **見つからなかったもの**：英語・日本語あわせておよそ40件を見た範囲で、上の最初の
  2つを重ねたもの——**読み方の制約を運ぶファイル名を、自分のファイルへ防御的に使う例**
  は出てきませんでした。この範囲で見つからないことは、存在しないことの証明では
  ありません。先行をご存じでしたら Issue でお知らせください。ここに明記します。
